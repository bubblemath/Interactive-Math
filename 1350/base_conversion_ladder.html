Multiply and add going in.
Divide and read up coming out.

Two directions, two procedures, and that's the whole skill. Going to base ten, each digit is multiplied by its place value and the products are added. Coming back, you divide by the base over and over and collect the remainders — but they arrive in reverse, so the last one you find is the first digit you write.

→ to base ten
multiply each digit by its place value, then add
← from base ten
divide by the base, then read the remainders upward
✋

Three mechanical traps, and they cause nearly every wrong answer. The remainders come out bottom-up, so writing them in the order you found them reverses the numeral. The place values are powers of the base — in base five the columns are 1, 5, 25, 125, not 1, 10, 100. And a base only owns b digits: there is no 5 in base five and no 2 in binary, so a numeral containing one isn't wrong, it's meaningless.

Why it matters

Base ten is a choice, not a law

It exposes what place value is

Nothing reveals the structure of our numerals like building the same quantity in another base. Students who can convert understand base ten better.

Binary runs the machine

Every file, image, and model on a computer is base two underneath. This is the rung where that stops being a slogan.

New digits, same idea

Base twelve needs symbols past 9, so T and E get invented. Seeing why makes the historical systems in this lesson feel inevitable.

Both directions are short procedures, and both fail the same way — by forgetting which base owns the place values, or which end of the remainders you started from. Powers of the base going in, remainders read upward coming out, and never write a digit the base doesn't have.
