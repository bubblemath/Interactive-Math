Regroup at the base,
not at ten.

The algorithm doesn't change at all. You still stack the numerals, add or subtract column by column, carry when a column overflows and borrow when it comes up short. Only the threshold moves. In base five a column overflows at five — so 4 + 4 = 8 is written 13₅: write 3, carry 1.

The carry threshold is the whole lesson. Carrying at ten in base five produces digits the base doesn't own — a giveaway that the wrong rule fired. Subtraction has the mirror-image trap: borrowing gives you five, not ten. In 33₅ − 14₅, the borrowed unit turns 3 into 8, not 13, so the answer is 14₅ and not 19₅. Watching yourself fumble this is the point — it's exactly what a six-year-old feels learning to regroup for the first time.

Why it matters

The best way to remember what learning feels like

You become the beginner again

You already know how to add. Working in base five puts you back where your students are — competent at the idea, clumsy at the execution. That memory is worth having.

Regrouping stops being a rule about ten

Carry when the column fills up. Borrow one group from the left. The base was never the point — the exchange was.

Illegal digits are diagnostic

A 7 in a base-five answer says exactly which rule misfired. Learning to read a wrong answer for its cause is a teacher's core skill.

Nothing about the standard algorithm depends on ten — it depends on there being a fixed point at which a column fills and trades upward. Find that point, carry and borrow against it, and the arithmetic you already know works in any base at all.
